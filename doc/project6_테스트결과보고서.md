## 1. 서론

### 1.1 문서 목적 및 범위

본 문서의 목적은 소프트웨어 개발 프로젝트 통합 관리 시스템 **DevTrack**에 대한 테스트를 수행하고 그 결과를 명시하는 데에 있다. 본 문서에서는 DevTrack 프로젝트의 테스트 기준, 테스트 범위, 테스트 케이스와 테스트 결과를 기술한다.

본 보고서는 실제 구현 이전의 **테스트 설계(Test Design)** 단계 산출물로, 요구사항분석서(DevTrack-REQ-001)에 정의된 유스케이스(U_01~U_10) 및 제약사항을 기반으로 사용자 시점의 블랙박스 테스트 케이스를 설계한다.

### 1.2 프로젝트 개요

DevTrack은 소프트웨어 개발 조직에서 요구사항, 일정(스프린트), 이슈, 산출물을 통합적으로 관리하는 웹 기반 프로젝트 관리 시스템이다. PM은 프로젝트·요구사항·스프린트를 관리하고, 팀원(Developer)은 이슈를 처리하고 산출물을 등록하며, 시스템은 알림 발송 및 기한 초과 감지 등 자동화 동작을 수행한다. React 기반 SPA, REST API, PostgreSQL 데이터베이스로 구성된다.

### 1.3 용어 정의

| 용어 | 설명 |
|------|------|
| 스프린트 (Sprint) | Agile-Scrum의 반복 개발 주기 단위 (1~4주) |
| 백로그 (Backlog) | 요구사항 및 작업 목록 (제품 백로그, 스프린트 백로그) |
| 이슈 (Issue) | 프로젝트 진행 중 발생하는 작업, 버그, 기능 요청 등의 단위 |
| 산출물 (Artifact) | 이슈·스프린트에 연결된 문서, 파일, URL 등 |
| 블랙박스 테스트 | 시스템 내부 구조를 모른다는 가정 하에 입력과 출력만으로 동작을 검증하는 테스트 기법 |
| SMTP | 이메일 발송에 사용되는 외부 인터페이스 프로토콜 |

## 2. 테스트 개요

### 2.1 테스트 범위

테스트는 시스템 내부를 모른다는 가정 하에 **블랙박스 테스트**로 이루어진다. 테스트의 범위는 아래와 같다.

| 범위 | 내용 |
|------|------|
| Web 기반 시스템 (Frontend) | Ⅰ. 브라우저 동작 정확성 확인 / Ⅱ. 요구사항 충족 확인 |
| REST API (Backend) | Ⅰ. 요청/응답 동작 정확성 확인 / Ⅱ. 응답 시간 등 비기능 요구사항 확인 |
| Database (PostgreSQL) | Ⅰ. 데이터 저장·조회 연동 시험 / Ⅱ. 데이터 입출력 확인 |

### 2.2 테스트 항목 및 통과 기준

**기능별 테스트 항목**

| 테스트 항목 | 관련 UC | 통과 기준 |
|------------|---------|-----------|
| 팀원 초대 기능 | U_02 | 유효한 이메일·역할 조합만 초대에 성공한다 |
| 프로젝트 생성 기능 | U_01 | 필수 항목이 채워지고 날짜 제약을 만족할 때만 생성에 성공한다 |
| 요구사항 등록 기능 | U_03 | 제목이 입력된 요구사항만 등록에 성공한다 |
| 스프린트 생성 기능 | U_04 | 진행 중인 스프린트가 없을 때만 정상 생성된다 |
| 이슈 할당 기능 | U_05 | 미할당 이슈만 스프린트에 할당되고 중복 할당은 차단된다 |
| 이슈 상태 변경 기능 | U_06 | 본인에게 할당된 이슈의 상태만 변경할 수 있다 |
| 산출물 등록 기능 | U_07 | 50MB 이하 파일/유효 URL만 등록에 성공한다 |
| 대시보드 조회 기능 | U_08 | 스프린트 데이터를 정확히 집계·렌더링한다 |
| 알림 발송 기능 | U_09 | 이벤트 발생 시 대상 멤버에게 알림이 정확히 발송된다 |
| 기한 초과 감지 기능 | U_10 | 마감일이 지난 미완료 이슈를 감지하고 알림을 트리거한다 |

**비기능별 테스트 항목**

| 테스트 항목 | 통과 기준 |
|------------|-----------|
| 브라우저 호환 테스트 | Chrome, Firefox, Edge 최신 버전에서 정상 작동·동일 렌더링 |
| 성능 테스트 | 일반 조회 REST API 응답 시간이 2초 이내 |
| 보안 테스트 | 로그인하지 않은 사용자가 시스템을 이용할 수 없고, 비밀번호가 bcrypt로 해시 저장된다 |

## 3. 테스트 케이스

### 3.1 테스트 케이스 선정

테스트 케이스는 본문 2.2의 테스트 항목에 따라 선정하였으며, 블랙박스 테스트 기법을 기반으로 시스템 내부 확인 없이 사용자 시점에서 검증 가능한 케이스 선정에 중점을 둔다. 각 유스케이스의 정상 흐름(Normal Flow)과 예외 흐름(Alternate / Exceptional Flow)을 모두 케이스로 도출하였다. 본문 3.3에서 기능별 테스트 케이스 목록을 나열한다.

### 3.2 테스트 케이스 유형

- 입력값 유효성 검증을 위한 **문자열/값 입력 테스트 케이스** (이메일, 날짜, 파일 크기 등)
- 기능 동작 확인을 위한 **동작(Yes/No) 테스트 케이스**
- 예외 상황(권한 없음, 중복, 서버 오류 등) 처리 확인을 위한 **예외 흐름 테스트 케이스**

## 4. 테스트 예외사항

### 4.1 중단 기준과 재개 조건

| 중단 기준 | 재개 조건 |
|-----------|-----------|
| 입력 타입과 다른 형식의 값이 입력되었을 때 (예: 이메일 필드에 비이메일 문자열) | 입력을 중단하고 유효성 오류 메시지를 표시한 뒤, 기존 데이터를 유지한 상태로 재입력을 받아 재개한다. |
| 데이터 집계·저장 중 서버(DB) 오류가 발생했을 때 | 마지막으로 캐시된 데이터를 표시하고 '일부 데이터가 최신이 아닐 수 있습니다' 경고 후, 서버 복구 시 재개한다. |
| 알림 발송 중 이메일 서버 연결이 실패했을 때 | 인앱 알림만 즉시 발송하고, 이메일은 최대 3회 재시도 큐에 등록하여 연결 복구 시 재개한다. |

## 5. 테스트 환경

### 5.1 테스트 환경 구성도

DevTrack은 브라우저 클라이언트가 REST API 서버를 통해 PostgreSQL DB와 통신하며, 알림 발송을 위해 외부 SMTP 이메일 서버와 연동되는 구조이다.

```
                    ┌─────────────────────────┐
                    │   PostgreSQL (Server DB) │
                    └────────────┬────────────┘
                                 │ ▲
                                 ▼ │
                    ┌─────────────────────────┐      ┌──────────────────┐
                    │   REST API (Backend)     │─────▶│  SMTP 이메일 서버  │
                    └────────────┬────────────┘      │  (외부 인터페이스)  │
                                 │ ▲                  └──────────────────┘
                                 ▼ │ (JSON / HTTP)
                    ┌─────────────────────────┐
                    │  Web System (React SPA)  │
                    └────────────┬────────────┘
                                 │ ▲
                  ┌──────────────┴──────────────┐
                  ▼                             ▼
        ┌──────────────────┐         ┌──────────────────┐
        │  Test Client 1   │         │  Test Client 2   │
        │  (Chrome 데스크탑) │         │  (Firefox/Edge)  │
        └──────────────────┘         └──────────────────┘
```

| 구성 요소 | 환경 |
|-----------|------|
| Test Client | Chrome, Firefox, Edge 최신 버전 (데스크탑) |
| Web System | React 기반 SPA |
| Backend | REST API 서버 (JSON / HTTP) |
| Database | PostgreSQL |
| 외부 인터페이스 | SMTP 이메일 서버 (초대·알림 발송) |
